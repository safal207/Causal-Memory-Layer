# CAEP official MCP Python SDK adapter

This reference adapter replaces the transport-neutral filesystem orchestration demo with real Model Context Protocol sessions using the official Python SDK.

```text
MCP client
  ├─ stdio session → payment action server
  └─ stdio session → independent verifier server
                         ↓
                    CAEP bundle
                         ↓
                    Trust Console
```

## What is proved

- the client performs the MCP initialization handshake with two separate server processes;
- tool discovery is checked before execution;
- observations, writes, compensation, and verification are invoked through MCP tool calls;
- the verifier is a separate MCP server process from the action executor;
- the happy transition, divergence record, and digest-bound recovery record pass the canonical `caep.schema.json` and `validate_caep.py` checks;
- the generated bundle can be opened by CML Trust Console.

The recovery scenario deliberately inserts a parallel ledger event after the MCP observation and before the MCP write. This creates a stale-state duplicate payment even though the action tool itself returns success. The independent verifier detects two successful payments, the client invokes `cancel_payment` through MCP, and a second verification confirms recovery.

## Run

From the repository root:

```bash
python -m pip install -e ".[mcp]"
python docs/experimental/caep/mcp_sdk_adapter/run_adapter.py \
  --output /tmp/caep-mcp-sdk-bundle.json
```

Expected summary:

```json
{"caep_validation":"valid","diverged":"diverged","happy":"verified","recovered":"verified","transport":"mcp-stdio"}
```

Open the output in the public Trust Console or inspect the generated JSON directly.

## Boundaries

- The user-facing optional MCP extra accepts the stable MCP Python SDK v1 line; the evidence test runtime is fixed to `mcp==1.29.0` for reproducibility.
- `stdio` is used for a deterministic local reference run. Streamable HTTP, authentication, discovery across remote deployments, and production persistence are separate concerns.
- A real MCP session proves protocol-level invocation and discovery, not that MCP itself standardizes CAEP.
- `validate_caep.py` remains the normative prototype validator. The Trust Console remains a presentation and browser-side digest-preview layer.
- The parallel event is intentionally outside the client-controlled MCP action session to model a concurrent external actor.
- Reproducible integrity and CI provenance do not establish publisher identity, production safety, or external endorsement.
